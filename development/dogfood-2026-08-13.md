## 样本

### D1：L1 active 注入 + Stop block — verified

临时目录：`tc init --agent claude` → `tc enable always` → `tc task new --level 1` →
`tc run T-1`（active）→ `claude -p "Reply exactly TC_DOG1." --include-hook-events
--setting-sources user,project`。

session 日志（`~/.claude/projects/.../`）证据：
- `SessionStart:startup` hook_success：stdout 为完整 `tc-breadcrumb/v1`——
  `{"task":{"id":"T-1","level":1,"status":"active","node":"execute-1",
  "nodeKind":"execute"},"next":{"command":"tc run complete T-1"}}` ✓
  （只注入定位信息 + 唯一 next，无上下文倾倒）
- `Stop` hook：exit 2（block，输出 breadcrumb）✓；loop guard 放行后模型正常结束。

### D2：waiting 状态静默 — verified（设计意图）

D1 基础上 `tc task wait T-1 --reason needs_input --message "..."`（waiting）→
`claude -p "Reply exactly TC_DOG2."`。

行为：**零注入、零 hook 输出**（entry.sh 手动执行确认 exit 0 零输出）。这是
`decideEntry` 的设计意图——waiting 时任务等待用户输入，Agent 应停止继续，
不注入推进指令；claude 对零输出 hook 不产生 hook_success 记录。Stop 允许结束。

### D3：跨会话恢复注入 — verified

D1 同目录（同一 Task Store）：`tc task resume T-1 --resolve` → `tc run T-1`
（active）→ **新 claude -p 会话**（`claude -p "Reply exactly TC_DOG3."`）。

session 日志：`SessionStart` 注入 `status=active / node=execute-1 /
next=tc run complete T-1` ✓；`Stop` exit 2（block）✓。**同目录二次会话注入
成功——中断后从 Task Store 恢复路径成立**。恢复后经公开 CLI `tc run complete`
可达 done（Task 02-06 既有测试覆盖完整闭环）。

### D4：L2 review 阶段注入 — verified（2026-08-13 补）

临时目录 L2 闭环：`task new --level 2` → frame/execute 完成 → `review start`
（active，next 指向 review pass）→ `claude -p "Reply exactly TC_L2A."`。

session 日志：`SessionStart` 注入 `status=active / node=review-1 /
nodeKind=review / next=tc review pass T-1 --attempt att-T-1-review-1-1
--reviewed-attempt att-T-1-execute-1-1` ✓——L2 review 阶段 breadcrumb 注入
（含 review pass 命令与 attempt id）。

### D5：L2 done 后零注入 — verified（2026-08-13 补）

D4 同目录完成 L2 闭环（review pass → record → done）后 `claude -p
"Reply exactly TC_L2B."`：session 无 SessionStart hook 记录——done 状态
`decideEntry` 静默（Agent 应结束），与本地矩阵一致 ✓。

### D6：Codex SessionStart 注入 — verified（2026-08-13 复验，推翻 S2 limited）

S2 的 limited 结论根因定位：`codex exec -c` 的 hook command 用
`command="bash '/path/entry.sh'"`（单引号嵌套）导致**命令解析失败**，hook
静默未执行；hooks 机制本身可用。复验（`codex exec --json -c
'hooks.SessionStart=[{provider="command",command="bash <path>/entry.sh"}]'`）：
模型判定上下文含 `tc-breadcrumb/v1` → **BREADCRUMB_SEEN** ✓。SessionStart
注入与 claude 同路径。

### D7：Codex Stop hook — limited（exec 非交互不触发）

marker 文件副作用测试（`hooks.Stop=[{provider="command",command="echo
STOP_RAN > /tmp/marker"}]`）：**marker 未生成——codex exec 非交互模式下
Stop hook 不执行**（SessionStart 执行、Stop 不执行；与 Task 00 探针
CX-02 的 0.146.1/0.147.0 Stop verified 记录矛盾，差异未定位）。伪 TTY
交互模式（`script`）TUI 无法自动化驱动（需真实 TTY 交互），超时终止。
**结论：Codex Stop hook 需在交互会话人工复验。**

# Evals 批量执行、可信判定与真实 Agent 场景

## Goal

让 QA 在提交版本上用一条命令运行 Evals，结果可续跑、可解释，并补齐两种真实 Agent 使用场景。

## Background

现有 Evals 有 delivery、recovery、review 三个 L1 案例、独立 code/model grader 和只读中文看板。仓库已有 CLI/核心协议测试，不需要在 Evals 重建一套协议测试平台。用户已检查五条并行队列，并于 2026-09-10 明确批准开始、使用 Luna/max 子代理、创建新分支并在完成后提交推送。

## Requirements

- R1：批量入口选择多个案例，支持重复次数、有界并发、结果持久化和中断续跑；终态失败记录不能丢失或被静默重跑替换。
- R2：没有独立 code 检查不能通过；无法判断与通过/失败间的变化不得称为能力改善或退步。看板显示批次的通过、失败、无法判断与未完成数量。
- R3：judge 根据需求、产物和执行事实独立评分，不预先读取 code grader 的判定；保留可抽查的依据，独立子代理审查固定样本。模型审查不能覆盖可靠代码失败，也不能冒充人工校准。
- R4：新增 L2 Review 退回、修复、再审、Record 场景；检查产物、reviewed attempt、successor、历史保留及最终 done。Review 独立性按实际能力披露。
- R5：新增正常会话结束后的恢复场景。首次必须正常退出且留下未完成任务，第二次为全新上下文，通过持久状态续接而非重建任务/重复 attempt。
- R6：新案例完整提供中文背景、任务、步骤、验收与证据说明；历史报告不修改，原有单案例入口继续可用。
- R7：在 feat/evals-batch-and-scenarios 分支交付；本地完成自动化验证与独立审查后提交并推送 origin。

## Acceptance

- A1：测试证明并发上限、重复次数、局部失败隔离、报告持久化、已完成作业跳过、运行中断后的可恢复状态；取消行为不遗留正在运行的子进程。
- A2：空 code、judge 不可判、代码硬失败、批次计数和旧报告兼容均有针对性回归测试。
- A3：judge prompt 不含 code 检查结论；真实产物/执行证据仍可用；无效或不足证据保持 inconclusive。
- A4：两个新场景有使用真实 tc CLI、可控 fake host 的正反例测试；场景缺少真实阶段或关联关系错误时不会通过。
- A5：类型、lint、format、全套自动测试和看板桌面/移动 smoke 通过；独立审查无未解决的实质缺陷。
- A6：远端分支存在并与最终本地提交一致；交付说明明确真实模型测评尚需走 QA 发布流程。

## Scope boundaries

保留三态 verdict、独立只读看板、现有 QA Git SHA 溯源和浅层目录。此次不增加构建内容哈希、L3 测评、数值总分、常驻调度服务、容器平台、35 个重复协议用例或本地付费模型测评。不改用户宿主/认证配置，不改历史 runs。

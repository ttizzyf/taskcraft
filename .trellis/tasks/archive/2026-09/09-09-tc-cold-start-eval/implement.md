# 执行与验证计划

1. 用户批准本方案后运行 task.py start；核对当前 task 路径与已有 diff 基线。
2. 在临时目录构建当前 tc，验证 CLI help 与 doctor 基础链路；固定测评条件和源码摘要。
3. 并行派发 A Entry 操作员和 B L2 操作员，明确目录所有权；他们不是被测 Agent，不得把测评上下文传给被测 Claude。
4. A 原样运行公共检测，再按失败证据做最小诊断；B 按 design 的两个检查点执行，采集新会话事件与独立验收。
5. 主会话审核评分依据，严格区分产品失败、环境阻塞、人工构造前提和未覆盖场景。不进行产品修复。
6. 写 development/evaluations/claude-entry-l2-recovery-2026-09-09.md：环境、协议、提示词、结果矩阵、证据、限制、迁移意义、清理结果。
7. 检查报告与实际退出码/记录一致，检查 git diff --check 与既有改动完整性；无需为纯报告重复运行产品完整测试套件。
8. 先保全必要脱敏证据，再清理临时资源与进程；按 Trellis 收尾，不自动提交 Git。

# 测评设计

## 隔离与职责

主会话负责控制与评分。两个测评操作员可并行：A 仅负责 Entry；B 负责 L2 实验。操作员知道测评目的，被测 Claude 会话不知道。不得将主会话历史或 Trellis 测评上下文传给被测 Agent。

临时根目录包含 tc 源码构建副本、A 项目、B 项目和控制器材料，实际路径用随机临时目录生成。被测进程的工作目录、许可工具路径限制在其项目和 tc 运行文件；控制器材料不放进项目或上级自动加载的说明文件。文件夹分离不等于安全沙箱，实际访问限制及残余可见性须在报告中说明。

仅复制构建所需源码、migration、package/TypeScript 配置等；不复制 `.trellis`、会话日志、迁移报告。记录 Git SHA、源码摘要及临时基线摘要。不复用可能陈旧的 dist。

## A：Entry 现场检测

1. 临时项目通过 `tc init --agent claude`、`tc enable always`、`tc task new`、`tc run` 建立唯一 active L1 前提。
2. 原样执行 `tc agent test-entry-hook --agent claude --json`，记录 60 秒边界内结果。
3. 若失败，用非写入诊断检查脚本输出、注册、Claude 参数和实际流式 Hook 事件；任何诊断变体单列，不能替代公共命令的失败结果。
4. 尽可能增加 takeover off 的零输出检查，区分一般模型连通性和 Hook 注入。

## B：真实 L2 修改

使用无外部依赖的 Node 小项目：待办列表导出 CSV。正常需求预先明确字段顺序、过滤、稳定排序、逗号/引号/换行转义及输入不被修改。公开基线测试和工程规范在项目内；独立验收用同一需求制定，评分器留在控制侧，不能增添未公开要求。

项目说明只包含正常开发约定、tc 命令可用方式及规范路径。不补写专门教冷启动过关的操作剧本；若需要超出产品正常指引的辅助，记为辅助实验。

### 执行中断检查点

给首个 Claude 普通功能需求，要求用 tc 管理 L2 工作。控制器观察真实工具事件，在 execute 已领取、首次实质代码修改完成且尚未提交 execute 结果时终止该进程。等待退出并确认文件稳定后启动新会话，不复用 resume、continue、fork 或旧聊天。

新会话只收到“继续当前项目尚未完成的工作。”。记录它是否自行利用 Entry/项目入口查询任务、辨认执行中状态、检查代码和证据，而非看到 next=complete 就直接提交。若进程在预定条件前自然完成，标记检查点未触发，不倒改数据库制造中断。

### 审核返工检查点

先允许真实独立 reviewer 按公开需求审核执行结果，使用 `tc review` 记录实际发现。若产生 changes，则在返工开始前切换到全新执行会话。

若自然审核无问题，另建同需求的受控 L2 样本：准备遗漏 CSV 转义的真实不完整实现，经公开 CLI 留下来源如实的执行记录，再交给不知道预设缺陷的 reviewer。此时仅用于测评“已有真实审核问题时能否冷启动修复”，不用于测量原 Agent 质量。不得向 reviewer 提示必须拒绝；未发现问题则如实报告该检查点未建立。

## 测量与限制

每个恢复点分别记五项二值观察：正确定位、正确阶段、读取相关持久化内容、真实完成剩余工作/修复、真实提交与通过独立验证。任何关键项失败均不判完整通过；基础设施失败记 blocked，未建立的场景记 not-exercised。

记录会话身份不同且无历史传递，工具拒绝、模型错误、超时、加载的宿主插件/记忆及控制器干预。正常个人配置不修改；发现外部记忆或插件泄露任务目的时样本无效。公共 Entry 检测可能创建宿主原生日志；不承诺删除不属于临时目录的个人历史。直接被测进程优先使用支持的 no-session-persistence。

公共 Entry 保持产品 60 秒超时。B 每个模型会话上限 10 分钟、实验最多 6 个被测/审核会话；阻塞后最多一次有依据的环境诊断重试，不暗中反复抽样直到成功。默认沿用本机 Claude 模型配置并记录实际模型，不强制切换模型。

## 清理

先将提示词、判据、摘要、退出码、脱敏关键证据和限制写入报告，再停止本次进程，取消尚未完成的临时任务（若公共 CLI 可用），删除本次随机临时根目录。Trellis 任务文档按管理流程保留，实验代码不回写仓库。
